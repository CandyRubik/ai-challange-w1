# RubikStudyHarness

Небольшой стенд для Дня 8: чат с подсчётом токенов и лаборатория «иголка в стоге сена».

Что показывает интерфейс:

- токены текущего сообщения, полной истории, входа и ответа модели;
- накопительный расход и оценочную стоимость по ходам;
- отличие локального подсчёта от фактического `usage`, возвращённого DeepSeek;
- поведение короткого и длинного диалога;
- `reject` и `trim` при приближении к лимиту контекста;
- поиск уникального факта в документе точного токенного размера;
- отдельный тест исходной идеи с документом ровно 5 MiB;
- безопасное переполнение: тест 1.05M останавливается до вызова модели.

## Запуск

Требуется Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
```

Заполните `DEEPSEEK_API_KEY` в `.env`, затем экспортируйте переменные и запустите сервер:

```bash
set -a
source .env
set +a
uvicorn app.main:app --reload --port 8000
```

Откройте <http://127.0.0.1:8000>. При первом запросе приложение скачает официальный `tokenizer.json` DeepSeek в `data/`; каталог исключён из Git.

## Как снять видео

1. Отправьте короткое сообщение и покажите карточки токенов.
2. Сделайте 4–6 ходов: на графике растёт вход модели и стоимость сессии.
3. Поставьте маленький лимит контекста и `Остановить`, покажите ошибку переполнения.
4. Переключите на `Удалять старые ходы`, повторите запрос и покажите число удалённых сообщений.
5. Запустите 10K-тест в начале, середине и конце документа. В результате должны совпасть ожидаемый код и ответ.
6. Покажите одновременно `Документ: 10 000 токенов` и фактический вход API — он немного больше из-за инструкции и chat template.
7. Запустите 1.05M: модель не вызывается, интерфейс показывает величину превышения.
8. При желании запустите ровно 5 MiB. Это дорогой реальный запрос, поэтому интерфейс спрашивает подтверждение.

## Проверки

```bash
pytest -q
python -m compileall -q app
```

Важно: документ считается официальным токенизатором точно. Полная упаковка сообщений до ответа остаётся оценкой, потому что chat template применяется на стороне API. После ответа поле `prompt_tokens` из `usage` является источником истины.
